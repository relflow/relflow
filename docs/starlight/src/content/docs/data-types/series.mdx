Use `rf.Series` when each record carries one run of numbers whose order
matters, such as the daily spend of an account over the last 90 days. Each step
carries `n_dim` numeric values, such as daily amount spent and daily
transaction count. Steps are ordered, not timestamped. When each step needs its
own fields, time gaps, or per-row outputs, use a
[chronological branch](/advanced/chronological-branches/) instead.

```python
import relflow as rf

model = rf.Model(
    preset="small",
    recent=rf.Series(n_dim=2, length=90, overflow="tail"),
    next_week=rf.Series(n_dim=2, horizon=7, mask=True),
)
```

## Input values

Each valued input takes one of three shapes. Each row below shows the same
three steps of temperature and humidity:

| Shape | Arrow type per record | Example record | Field |
| --- | --- | --- | --- |
| list | `list<number>` | `[21.5, 22.0, 22.4]` | `rf.Series(n_dim=1)` |
| list of lists | `list<list<number>>` or `list<fixed_size_list<number, C>>` | `[[21.5, 0.61], [22.0, 0.58], [22.4, 0.55]]` | `rf.Series(n_dim=2)` |
| columnar sources | one `list<number>` per channel | `{temp: [21.5, 22.0, 22.4], hum: [0.61, 0.58, 0.55]}` | `rf.Series(query=("ett.temp", "ett.hum"))` |

Large lists and fixed-size lists are accepted wherever lists are. Values
convert to float64; integers beyond ±2^53 are rejected. Struct steps, such as
`list<struct<temp: number, hum: number>>`, are not read; turn each step into a
list of its numeric members in a preprocessor.

`n_dim` is required for a single query because layers are built before any
data is read. A tuple `query` reads one source per channel, in tuple order, and
sets `n_dim`; an explicit `n_dim` must equal its length. Every source must
select the same steps. Tuple sources also name the members of each forecast
step.

A step is observed only when every one of its channels is finite. A null, NaN,
or infinite value makes its step unobserved: the rest of the series stays
valid, and the encoder sees which steps were observed. relflow does not impute
missing values or keep partially observed steps. With a tuple query, a null
source list is a missing channel at every step of the record. When every source
list is null, the series is null. Valid source lists of different lengths raise
an error naming the field, the queries, and the first record that differs.

An empty series is `valued`. A non-empty series with no observed step takes the
`other` state. A null series is `null`.

## Standardization and processor pipelines

Per-channel statistics learned from training observations standardize the
steps. Standardized steps pass through a linear projection to the model width,
then `n_blocks` residual blocks of two dilated convolutions with dilation
doubling at each block. A masked max-pool collapses the result to one token, so
the field adds one token to its record however long the series is. Padding and
unobserved steps never contribute, and an embedding does not depend on the
padded width of the batch.

With `n_blocks=k`, each step feature sees up to `1 + 4 * (2^k - 1)` neighboring
steps: 253 at the default of six. The max-pool then covers every retained
observed step. Choose `n_blocks` for the local patterns that matter, and apply
`length` to bound memory. Training jitter perturbs input steps; it never changes
a forecast target.

`Series` does not read elapsed time. Use a chronological branch with
`time_index`, [Period](/data-types/period/), or a derived
[Number](/data-types/number/) for irregular sampling.

## How is this leaf trained?

As a forecast target, `Series` predicts `horizon` steps of `n_dim` values from
the context of the record. The loss is the `objective` error over target steps
observed in the source, after both sides are standardized per channel. MAE and
RMSE metrics report in source units. A target shorter than `horizon` has
unobserved slots for the remaining steps; a longer target raises.

`horizon` is required on reconstruction targets (`mask=True` or a
reconstructing ancestor) and rejected otherwise. Classify a series by pairing it
with a sibling target such as `label=rf.Category(mask=True)`. `embed=True`
exports a series embedding of the model width.

### Predictions

`content` is a list of exactly `horizon` steps, decoded back to source units.
With a single query, each step is a list of float64 values; with a tuple query,
each step is a struct with one float64 member per query text, in tuple order.
These are predicted values, not future observations. A forecast target does not
need its source columns at prediction time. Parquet round-trips these variable
lists, including inside a branch with null items.

## Leaf-specific parameters

| Option | Default | Purpose |
| --- | --- | --- |
| `n_dim` | Required unless `query` is a tuple | Positive number of values per step. |
| `length` | `None` | Hard cap on retained input steps. `None` keeps the whole series. |
| `overflow` | `None` | With a finite `length`: `"head"` (default), `"tail"`, `"random"`, or `"error"`. |
| `horizon` | `None` | Steps to predict on a reconstruction target. |
| `n_blocks` | `6` | Number of dilated convolution blocks. |
| `jitter` | `rf.Jitter()` | Training noise on input steps. |
| `objective` | `"l2"` | Forecast loss: mean `"l1"` or `"l2"` error over predicted steps and channels. |

Overflow follows branches: use `"tail"` for recency-ordered history. With
`"random"`, training draws a contiguous window of steps and later phases keep
the tail.

### Request methods

This type has no type-specific request methods.

## Errors raised

| When | Failure | What to check |
| --- | --- | --- |
| A single query without `n_dim`, or `n_dim` that disagrees with a tuple query | Configuration validation rejects the width. | Declare `n_dim`, or let the tuple set it. |
| `horizon` missing on a target or set on an input | Configuration validation rejects the field. | Set `horizon` only on reconstruction targets. |
| A step with the wrong number of channels | `ValueError` names the expected width. | Validate step widths before fitting or prediction. |
| Tuple sources of different lengths in one record | `ValueError` names the field, queries, and record. | Align the channel lists before reading them. |
| A forecast target longer than `horizon` | `ValueError` rejects the extra steps. | Trim targets to `horizon` steps. |

### Footguns

- **Expecting elapsed time.** Steps are positions only. Irregular sampling needs
  a chronological branch with `time_index` or a derived time input.
- **Using `mask=True` on history.** A masked Series is never embedded; keep
  history and forecast in separate fields.
- **Reading struct steps.** `list<struct<...>>` steps are not read; reshape them
  in a preprocessor or use a branch.
