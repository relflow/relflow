Use `rf.Number` for a measurement whose magnitude matters: an amount, count,
distance, or elapsed time. It learns from the supplied numbers and manages its
own numeric normalization.

<DataTypePage id="number-examples" examples={numberExamples}>

## Inputs

Supply numeric scalars, such as `29.95`, `4`, or `-2.5`. Zero is a value;
`None` represents a null. Keep units consistent within a field.

Number combines representations of the original value and a signed logarithmic
scale. It learns their normalization from training data, so you do not need to
choose a log transform or standardize the field before using it.

On CPU and CUDA, source values, statistics, and numeric readouts retain float64
precision. MPS uses float32. Integers beyond ±2^53 are rejected; choose
[Hash](/data-types/hash/) for large identifiers. A floating-point NaN takes the
`other` state; infinite values are excluded from numeric regression targets.

## Predictions

A numeric prediction returns in the same units as its training labels. In this
delivery example, `predictions.delivery_days.content` contains the predicted number of
days. The surrounding result also carries the field's state and whether it was
inferred. See [Runtime](/concepts/runtime/) for how targets fit into
the output record.

Error metrics are reported in the original units.

## Options

| Option | Default | Purpose |
| --- | --- | --- |
| `objective` | `"mae"` | Choose `"mae"`, `"mse"`, or `"huber"` for numeric reconstruction. |
| `alpha` | `None` | Use cumulative normalization statistics, or a value between 0 and 1 for exponential training updates. |
| `jitter` | `rf.Jitter()` | Configure training-only noise while preserving reconstruction targets. |
| `n_bands` | `8` | Set the number of Fourier bands per numeric representation. |
| `offset` | `4` | Set the Fourier exponent offset. |

MAE training combines signed-log and source-unit absolute error. MSE and Huber
train in the original units. Compare predictions with the metric that
represents your application.

## Request Methods

Inspect the training normalization of a Number field.

| Method | Returns | Purpose |
| --- | --- | --- |
| `normalization(model, address)` | Dictionary snapshot | Inspect the field's source-unit normalization statistics. |

For a trained delivery model held in `model`:

```python
statistics: dict[str, float | int | None] = rf.Number.normalization(
    model, "/order_total"
)
```

The returned dictionary contains `mean`, `variance`, `std`, `count`, and
`alpha`. `std` is the standardizing scale, including a small numerical floor.
With cumulative statistics, `count` is the observation count and `alpha` is
`None`. With exponential updates, `count` is `None` and `alpha` reports the
configured update rate. The method returns a snapshot, so editing the
dictionary does not change the model.

## Footguns

- **Using a learned sum as exact bookkeeping.** The retained six-number
  experiment learned an approximation with nonzero error; it did not establish
  exact addition. Compute balances and other exact arithmetic in preprocessing.
  [P039: six-number sum](/evidence/#P039)
- **Replacing missing measurements with zero.** This merges two distinct inputs.
  In the controlled null-versus-zero task, filling nulls removed the only useful
  signal. Preserve nulls when absence carries meaning.
  [P038: null-versus-zero controls](/evidence/#P038)
- **Sending integers beyond ±2^53.** Number rejects these values because its
  float64 representation cannot preserve every integer there. Use Hash for
  identifiers; keep exact large-integer arithmetic in your data preparation.
  [Precision-boundary test](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/tensorfields/extensions/test_number.py#L807-L810)
- **Choosing a numeric representation from one average score.** In P079's
  generated heavy-tail task, error relative to the known optimum was higher in
  the tail than in the bulk, and changed with the training budget. Check your
  important value ranges separately, using errors in their original units.
  [P079: bulk, tail, and budget comparisons](/evidence/#P079)
