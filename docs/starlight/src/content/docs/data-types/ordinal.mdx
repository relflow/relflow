Use `rf.Ordinal` when a value has an ordered position: a priority level, an
inspection grade, or an integer stage. It learns through numeric ranks, so
larger rank errors carry a larger distance.

<DataTypePage id="ordinal-examples" examples={ordinalExamples}>

## Inputs

Choose one of two contracts:

- **Declared labels:** `values=("low", "normal", "high")` maps labels to
  consecutive ranks `0`, `1`, and `2`. Tuple order defines their meaning; names
  do not supply an order or a distance. Every non-null input must match a
  declared label exactly. The declaration does not grow during training.
- **Integer ranks:** omit `values` to use source integers directly. Negative
  ranks and ranks absent from training are valid. Gaps retain their size:
  `10` to `20` is a ten-step difference. Booleans, floats, and numeric strings
  are rejected in this mode, and ranks must lie within ±2^53.

A declaration must contain unique labels of one scalar type: string, integer,
finite float, Boolean, or bytes. With `values=(10, 20, 30)`, those integer labels
instead occupy adjacent positions `0`, `1`, and `2`. Nulls keep a separate state;
they are neither labels nor integer ranks. String spelling and case must match;
Ordinal has no string-folding options.

Ordinal reuses Number's numeric encodings and learned normalization, with the
ranks as its numeric values. Using an ordered input does not force another
target to increase monotonically with that input.

## Predictions

An Ordinal target learns a numeric rank. Prediction writing rounds the readout
to the nearest integer, with halfway values rounded to the nearest even rank:
`0.5` becomes `0`, and `1.5` becomes `2`.

With declared labels, the rank is clamped to the declaration's first and last
positions and decoded back to the corresponding label. `content` preserves the
label's scalar type, so integer labels remain integers. Without `values`,
`content` is an integer rank clamped to ±2^53. Nonfinite readouts are rejected.

The rich result also carries `state` and `inferred`. Ordinal does not return
content probabilities or top-k candidates. Losses and numeric error metrics
operate on ranks before output rounding. A target inside a branch gets one
aligned result per supplied retained record, as in the inspection example.

## Options

| Option | Default | Purpose |
| --- | --- | --- |
| `values` | `None` | Declare an ordered tuple of labels, or leave unset for open integer ranks. Pass this option by keyword. |
| `mask` | `False` | Set `mask=True` to hide the field from inputs and learn it as a supervised target. |
| `objective` | `"mae"` | Choose `"mae"`, `"mse"`, or `"huber"` for numeric rank reconstruction. |
| `alpha` | `None` | Use cumulative rank-normalization statistics, or a value in `(0, 1)` for exponential training updates. |
| `jitter` | `rf.Jitter()` | Apply training-only noise to rank inputs while preserving targets. |
| `n_bands` | `8` | Set the number of Fourier bands per numeric representation. |
| `offset` | `4` | Set the Fourier exponent offset. |

Changing the declaration changes what learned ranks mean. A checkpoint with a
different declaration is rejected rather than silently reinterpreting its
learned state. Ordinal uses keyword `values=(...)`; the positional-label syntax
shown for Enum does not apply here.

## Request Methods

Inspect the numeric normalization of an Ordinal field with the inherited
normalization helper. For a trained review model from the first example:

| Method | Returns | Purpose |
| --- | --- | --- |
| `normalization(model, address)` | Dictionary snapshot | Inspect the learned normalization statistics of this field's numeric ranks. |

```python
statistics: dict[str, float | int | None] = rf.Ordinal.normalization(
    model, "/priority"
)
```

The snapshot contains `mean`, `variance`, `std`, `count`, and `alpha`. For
declared labels, these statistics refer to positions such as `0`, `1`, and
`2`, rather than to the label text or the magnitudes of numeric labels.
Editing the returned dictionary does not change the model. Ordinal has no
vocabulary or per-label counts helper.

## Footguns

- **Assuming numeric labels keep their original spacing.** Declared `values=(10, 20, 30)` assigns consecutive ranks `0`, `1`, and `2`; declaration order defines the ordering. Omit `values` when source integers and their gaps should be ranks directly, and check that the resulting distances match your task. The [rank encoding tests](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/tensorfields/extensions/test_ordinal.py#L56) distinguish these contracts.
- **Expecting a fractional rank to survive output writing.** The writer bounds the readout to the declared label range or supported integer range, then rounds to the nearest integer with ties to even. Inspect per-rank held-out errors and boundary behavior; use Number for a continuous readout. The [writer checks](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/tensorfields/extensions/test_ordinal.py#L224) cover rounding and saturation.
- **Reading state probabilities as label confidence.** `state` describes valued, null, padded, masked, and other states; Ordinal `content` has no class-probability distribution or top-k candidates. Use Enum or Category when you need those outputs. See the [Ordinal output contract](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/src/relflow/tensorfields/extensions/ordinal.py).
- **Treating accepted unseen ranks as demonstrated generalization.** Open integer ranks do not require vocabulary admission, but predictive quality on withheld ranks still needs evaluation. Hold out the ranks that matter in your application; [P100](/evidence/#P100) proposes this comparison and has no selected measurement in the retained publication.

## Related types

- [Enum](/data-types/enum/) predicts one of several declared classes without imposing numeric rank distances.
- [Category](/data-types/category/) learns a label vocabulary from training data.
- [Number](/data-types/number/) predicts a continuous numeric measurement without discrete rank decoding.
- [Quantile](/data-types/quantile/) represents numbers by position in a learned distribution rather than a declared order.
