title: Choose your data types
description: Give each value a meaning that relflow can use to build its representation and predictions.
---

A field type tells relflow what a value means and how to learn from it. An
amount has magnitude, a category identifies a label, and a timestamp can
provide calendar context. Those choices guide the model's representations
and the answers it can learn.

Choose types for their meaning in your problem. The number `17` could be a
quantity, a product label, or an identifier used to match records. Those are
different modeling choices even when the source stores them all as integers.

## Start with a record

```python
import relflow as rf


class SupportTicket(rf.Model):
    """A support request and the decision to learn."""

    message = rf.Text
    product = rf.Category
    priority = rf.Enum("low", "normal", "high")
    tags = rf.Set
    account_age_days = rf.Number
    needs_escalation = rf.Boolean(mask=True)
```

Each field reads the matching value in the input record. `message` contributes
the meaning of the request, `product` learns label-specific patterns, and
`account_age_days` retains numeric magnitude. `needs_escalation` is the answer
to learn, so its training label is kept out of the model's inputs.

Use a bare type when its defaults fit, such as `rf.Number`. Call it when you
need options, such as `rf.Boolean(mask=True)`. Enum labels are positional;
Vector requires an explicit width. Defining the class declares the contract.
Constructing `SupportTicket(...)` creates the model, and fitting it learns from
your examples.

Hover, focus, or tap the dotted terms in examples for contextual explanations.

## Find the meaning you need

| Your value represents… | Choose | Example |
| --- | --- | --- |
| A measurement whose magnitude matters | [Number](/data-types/number/) | Price, temperature, elapsed days |
| A number's position in a learned distribution | [Quantile](/data-types/quantile/) | Relative transaction size |
| Ordered labels or integer ranks | [Ordinal](/data-types/ordinal/) | Severity levels, ranked outcomes |
| A true or false condition | [Boolean](/data-types/boolean/) | Whether an item was returned |
| One label from a vocabulary learned during training | [Category](/data-types/category/) | Merchant, product family, region |
| One label from a list you declare | [Enum](/data-types/enum/) | `"low"`, `"normal"`, `"high"` |
| Unordered membership in several labels | [Set](/data-types/set/) | Tags, interests, enabled services |
| An identity used to match values across records | [Hash](/data-types/hash/) | Account or device identifiers |
| Repeated identities that can share predictive behavior | [Group](/data-types/group/) | Merchant or product groups learned through a task |
| Selected calendar cycles | [Period](/data-types/period/) | Weekday, month, hour |
| Elapsed time derived from timestamps | [Duration](/data-types/duration/) | Account age, time since a purchase |
| The meaning of a string | [Text](/data-types/text/) | A message or product description |
| Numeric coordinates with a fixed width | [Vector](/data-types/vector/) | An existing embedding or sensor signature |

Start with Number, Boolean, Category, and Enum for ordinary scalar fields.
Add the other representations when their semantics match your data. Group
learns shared identity representations when the field supplies visible context
to a prediction task. Use Ordinal when label order matters, and Enum when the
labels are alternatives without a numeric ordering.

## Keep records and values distinct

A list can have several meanings. `rf.Set` represents label membership;
`rf.Vector(n_dim=4)` represents four numeric coordinates. A list of orders,
each with an amount and a merchant, belongs in an `rf.Branch` with those fields.
Branches compose the same types at any depth.

## Shared field options

| Option | Default | Purpose |
| --- | --- | --- |
| `mask` | `False` | Configure hiding and reconstruction. `mask=True` defines a supervised target whose value is never embedded. |
| `embed` | `False` | Export a learned representation during prediction. This does not add a training objective. |
| `query` | `None` | Read from an explicit structural path instead of the matching field name. Transformations and joins belong in a preprocessor. |

Duration can read two timestamp paths to derive an elapsed value. Its field name
describes that derived value; the source record supplies the timestamp endpoints.

The field type determines what reconstruction means. A Boolean target learns
a probability; a Number target learns a numeric value. Text reconstruction
learns a representation and does not generate prose. Each page spells out
the input and prediction contract before listing its specific options.

Missing values also have a contract: zero, false, an empty collection, an
unknown label, and null can carry different meanings. Preserve those
distinctions in your input; the type pages explain how each is handled.
