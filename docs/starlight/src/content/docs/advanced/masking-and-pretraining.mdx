Use four schema options to declare what the model sees and learns.

| Option | Applies to | Behavior |
| --- | --- | --- |
| `predict: bool` | Leaf or child branch | Keep the answers out of the encoder on every split. Learn and score observed answers. At prediction, return an answer for each supplied position. A branch supervises all active descendant leaves. |
| `hide: rf.HideInput` | Leaf or branch, including the root | Replace selected training inputs with a masked placeholder. Keep row positions. This option adds no objective and has no effect during validation, test, or prediction. |
| `ablate: float` | Leaf or child branch | Drop the input and its targets during training. Draw once per record for a leaf or once per parent for a whole collection. |
| `task` | Leaf or branch, including the root | Declare a learning task. `rf.reconstruct(...)` hides selected observations and uses their original values as answers. |

`task: rf.Reconstruction | tuple[rf.Reconstruction, ...] | None` accepts one
reconstruction rule or a tuple. An observation supplies an answer if any rule
selects it.

```python
import relflow as rf

temperature_task: rf.Reconstruction = rf.reconstruct(rate=0.15)

model = rf.Model(
    preset="small",
    temperature=rf.Number(hide="sensor_offline", task=temperature_task),
    inspections=rf.Branch(
        predict=True,
        passed=rf.Boolean,
        repair_cost=rf.Number(ablate=0.1),
    ),
)
```

During training, a true `sensor_offline` flag hides the temperature. The task
independently samples temperatures to reconstruct at a rate of 15%. Each
inspection supplies two answers. Dropping a repair cost during training
keeps that inspection’s pass/fail answer and its row. At prediction time,
`inspections=[{}, {}]` requests both answers for two inspections in source order.
The [paired calibration experiment](/evidence/P128/) tests whether a branch
learns both answers when one leaf loses half its training observations.

A `hide` float is a probability from zero inclusive to one exclusive. A
string reads a Boolean selector from the source. A tuple combines selections:
`hide=("sensor_offline", 0.05)` hides values marked offline plus a sample of
the other values. An empty tuple or `0.0` disables input masking. A branch
shares one decision across a selected row's descendants. Its `ignore` option
accepts a direct child name or a tuple of names. An ignored child branch keeps
its subtree available, subject to its own policies.

```python
# Keep the hour visible when a whole sensor reading is marked offline.
sensor_readings = SensorReading(
    length=168, overflow="tail", hide=("sensor_offline", 0.05), ignore="hour",
)

# Sometimes a subscriber has no usable support history.
support_tickets = SupportTicket(length=32, overflow="tail", ablate=0.1)

# Reconstruct runs of neighboring sensor rows while keeping their hours.
sensor_pretraining = SensorReading(
    length=168, overflow="tail",
    task=rf.reconstruct(rate=0.15, span=4, ignore="hour"),
)
```

These examples use the maintenance and subscriber churn branch classes from
the [model use cases](/concepts/models/#explore-a-use-case).
The `sensor_offline` selector is a Boolean supplied on each sensor row.
`ablate` takes a float from `0.0` to `1.0` inclusive. Use `1.0` to simulate
an unavailable field or collection throughout training.
The [history ablation experiment](/evidence/P130/) scores the same fitted model
with a restored history, an empty history, and another record's history.

With `task=rf.reconstruct()`, every observed value supplies a reconstruction
answer and every selected position is requested at prediction time. A rate of
`0.0` disables that rule. A rate of `1.0` selects every eligible position,
including at prediction time, regardless of span. On a
branch, every reached leaf needs a decoder and a loss. Exempt input-only
children from reconstruction by naming them in `rf.reconstruct(ignore=...)`.

Sampled validation and test selections repeat for a fixed seed, split, and
batch plan. At prediction, a fractional rate requests no answers. Use
`rf.reconstruct(query="needs_estimate")` to request specific positions.
Training also uses the current epoch. Changing batching or row
order can change the sample. Small batches, empty histories, and queries that
select nothing can leave a batch without a reconstruction answer.

## Pretrain on context, then add the business target

Use the maintenance example's observation boundary: one asset at an assessment
cutoff, with sensor readings and completed work known then. The eventual
supervised task predicts failure within the next 30 days.

<DataViews id="pretraining-maintenance-data" dataset={observationDatasets.maintenance} schema={scenarios.filter((item) => item.id === 'maintenance')[0].schema} />

The explorer describes the final task. The pretraining schema below uses its
context fields without `failure_30d`: sampled temperature and load readings
supply reconstruction answers directly from the observed history.

Prepare `maintenance/pretrain/train.parquet` and
`maintenance/pretrain/validation.parquet` with those context fields. Every
retained reading must precede the assessment cutoff. Keep histories ordered
oldest to newest so `overflow="tail"` keeps the most recent retained records.

```python
import relflow as rf


class SensorReading(rf.Branch):
    """One sensor observation available at the asset assessment."""

    hour = rf.Period("hour_of_day")
    vibration = rf.Number
    temperature = rf.Number(
        task=rf.reconstruct(rate=0.15),
        weight=0.25,
    )
    load = rf.Number(
        task=rf.reconstruct(rate=0.15),
        weight=0.25,
    )


class WorkOrder(rf.Branch):
    """One completed maintenance job known at the assessment."""

    type = rf.Category
    parts_replaced = rf.Set
    age_days = rf.Number


class AssetPretraining(rf.Model):
    """An asset whose observed sensor context supplies pretraining tasks."""

    asset_type = rf.Category
    age_years = rf.Number
    sensor_readings = SensorReading(length=168, overflow="tail")
    work_orders = WorkOrder(length=32, overflow="tail")


if __name__ == "__main__":
    model = AssetPretraining(preset="small")
    pretraining = rf.ArrowDataModule(
        train="maintenance/pretrain/train.parquet",
        validate="maintenance/pretrain/validation.parquet",
    )
    model.fit(
        pretraining,
        batch_size=128,
        learning_rate=1e-4,
        max_epochs=8,
    )
    model.save("asset-context.rf")
```

The two reconstruction addresses are `/sensor_readings/temperature` and
`/sensor_readings/load`. Their known source values are retained as answers
while selected encoder values are hidden. Masked placeholders retain the positions of those readings.

The validation objective here measures reconstruction of held-out sensor
values. It does not measure the future failure task. Compare fine-tuning
against training that final task from scratch using the same evaluation
cohort and budget.

The sampled policies also do not request public prediction outputs by
themselves. Add the supervised target below before using `predict`, or request
[embeddings](/advanced/embeddings/) explicitly when you want learned context
representations from the pretrained artifact.

### Switch to the supervised objective between fits

Now prepare `maintenance/failure/train.parquet` and
`maintenance/failure/validation.parquet` with the same known context plus
settled `failure_30d` labels. That label keeps the original definition:
failure in the 30 days after assessment. The prediction requests file contains
known context without the answer.

```python
import polars as pl
import relflow as rf


model: rf.Model = rf.Model.load("asset-context.rf")

for field in ("temperature", "load"):
    address = rf.Address("sensor_readings", field)
    model.update(
        rf.where("address") == address,
        task=None,
        weight=1.0,
    )

root = rf.where("address") == rf.Address()
model.extend(root, failure_30d=rf.Boolean(predict=True))

fine_tuning = rf.ArrowDataModule(
    train="maintenance/failure/train.parquet",
    validate="maintenance/failure/validation.parquet",
)
model.fit(
    fine_tuning,
    batch_size=128,
    learning_rate=5e-5,
    max_epochs=8,
)
model.save("asset-failure.rf")

requests: pl.DataFrame = pl.read_parquet("maintenance/failure/requests.parquet")
predictions: pl.DataFrame = model.predict(requests, batch_size=256)
```

This makes temperature and load ordinary context again and adds one fresh
Boolean head. Compatible learned state can survive the schema rebuild;
the new head still needs the supervised fit. The unqualified `model.fit`
starts a new optimizer run on the current parameters.

Perform edits outside active Trainer/forward/inference operations. Use
[Mutations](/advanced/mutations/) to understand what is retained or reset,
and [Checkpoints and state](/advanced/checkpoints-and-state/) when continuing
a training run rather than starting a new adaptation phase. Calling
`model.reset(...)` deliberately discards selected learned runtime state;
it is not required just to change masking policy.

## Drive selection from a source Boolean

Use a query when the application already knows which coordinates should be
hidden. For example, add a non-null `reconstruct_temperature` Boolean to
each sensor-reading source record. The selector is control data read by
the mask; it does not need to be declared as an embedded model field.

This alternative declaration builds on the classes above:

```python
class SelectedReading(SensorReading):
    """A reading with explicit temperature reconstruction selection."""

    temperature = rf.Number(
        task=rf.reconstruct(query="reconstruct_temperature")
    )


class SelectedAsset(AssetPretraining):
    """An asset whose temperature targets follow source selectors."""

    sensor_readings = SelectedReading(length=168, overflow="tail")
```

The query runs against the declaring node's records. Here, each retained sensor
reading. It must return one structurally present Boolean per owner record,
without nulls. A query is relflow's structural path syntax, not an arbitrary
Python expression. Compute joins, ranks, time windows, or eligibility in a
preprocessor or source pipeline, and provide the resulting Boolean column.

A query and a rate inside **one** reconstruction declaration select their
intersection. For example, `rf.reconstruct(query="sensor_offline", rate=0.2)`
samples 20% of eligible offline readings. To select **either** condition,
supply a tuple. This maintenance example selects every flagged temperature
and a sample of all temperatures:

```python
temperature = rf.Number(
    task=(
        rf.reconstruct(query="sensor_offline"),
        rf.reconstruct(rate=0.2),
    )
)
```

An overlapping reading supplies one answer at that field address. On a
branch, each declaration shares its row decisions across descendants and
applies its own `ignore` and `span` settings. At prediction time, the
query-only declaration still requests its selected temperatures.

For query-backed prediction, retain the selector and the queried source
structure; place nulls in selected value positions when appropriate rather
than assuming the entire field may disappear. Automatic omission of a source
target is supported by unconditional reconstruction such as `predict=True`.
The [selector validation tests](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/data/test_dynamic_masking.py#L191)
and [branch selection tests](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/data/test_mask_policies.py#L208)
cover these boundaries.

## Redact unavailable context before encoding

When a source flag marks an event as unavailable at the decision cutoff,
apply the same preprocessor during training, evaluation and prediction.
Replacing a flagged record with a null list element keeps the original
length and row order. The fourth event stays at position 3 even if the
second and third events are hidden.

```python
import polars as pl
import relflow as rf


@rf.preprocess
def redact_events(frame: pl.DataFrame) -> pl.DataFrame:
    event = pl.element()
    visible = pl.when(~event.struct.field("hidden")).then(event)
    return frame.with_columns(pl.col("events").list.eval(visible))


data = rf.ArrowDataModule(train="events/train.parquet", preprocessor=redact_events)
# Pass preprocess=redact_events to model.predict(...) for direct prediction.
```

For one field, clear only that value and keep its siblings. A null scalar is
an observed missing value. If a training answer should still be scored, keep
it in a target field or select it with `task=rf.reconstruct(query=...)`.
The [event spacing experiment](/evidence/P127/) measures the difference between
null slots and filtering rows out of the list.

### Score pending claims in a mixed batch

Suppose historical claims carry the eventual settled amount and a flag recording
whether that amount was pending at the decision cutoff. Train on those records,
then score incoming claims with the same flag. The request includes a nullable
numeric `amount` column. Pending claims can have a null amount.

```python
import polars as pl
import relflow as rf


class ClaimReview(rf.Model):
    """Estimate the settlement for claims still pending at the cutoff."""

    billed = rf.Number
    amount = rf.Number(
        task=rf.reconstruct(query="pending_review"),
    )


if __name__ == "__main__":
    model = ClaimReview(preset="small")
    data = rf.ArrowDataModule(
        train="claims/train.parquet",
        validate="claims/validation.parquet",
    )
    model.fit(data, preset="small")

    requests = pl.read_parquet("claims/requests.parquet")
    result = model.predict(requests, retain=("claim_id",))
    amount = pl.col("predictions").struct.field("amount")
    estimates = result.filter(amount.struct.field("inferred")).select(
        pl.col("inputs").struct.field("claim_id"),
        amount.struct.field("content").alias("estimated_amount"),
    )
```

For a pending claim, the model uses the billed amount as context and infers the
settlement. For a settled claim, the settlement stays visible and `inferred`
is false. A supervised `amount = rf.Number(predict=True)` instead requests an
estimate for every claim and allows the entire amount column to be omitted.

## Combine objectives deliberately

A field may combine `hide` with a `task` objective. Training
hides the union of their selections and scores the observed answers selected
for reconstruction. Put `ignore` on the branch to exempt children from
ordinary masking, or on `rf.reconstruct(...)` to exempt them from that
pretraining objective. Each supervised or reconstructed field has one
objective address.

By default, relflow computes one extension-owned loss per participating
reconstruction address, multiplies it by the field's positive `weight`,
and sums those weighted losses. A masking rate therefore changes which
coordinates participate; `weight` changes the contribution of an objective.
Different types, units, and reconstruction tasks need separate evaluation.
The [loss aggregation](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/src/relflow/architecture/runtime.py#L330)
defines that distinction.

The optional `jacobian=True` constructor policy uses TorchJD UPGrad to
combine weighted reconstruction objectives. It requires `relflow[torchjd]`,
dense objective gradients, and single-device or unsharded DDP training.
Enable it before compilation; it is a session policy that must be selected
again after loading a model. See the
[policy validation](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/src/relflow/architecture/jacobian.py#L29)
before integrating it with a custom training loop.

## Keep the prediction cutoff outside the mask

Random reconstruction allows other retained records to inform a selected
answer. For the maintenance task, ensure the source history was already
cut at the assessment time. Hiding a value does not remove future records,
join leakage, or an answer duplicated in another input field.

A reconstruction mask controls value visibility and objective selection;
it does not introduce a causal attention policy or generate a sequence of
future records. The [attention implementation](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/src/relflow/architecture/attention.py#L69)
uses the retained context. Build an explicit prefix/cutoff task when the
evaluation question requires past-only information.

Masking also leaves pristine training observation intact: the vocabulary
and numeric statistics can still learn from the source values before the
masked input projection. Use validation/test splits to freeze that state,
rather than treating hidden training values as a held-out population.
See the [pristine-observation tests](https://github.com/relflow/relflow/blob/a1d0be3e373cf6c183e4926f1bfcbef845f2f883/tests/data/test_dynamic_masking.py#L90)
and [Online vocabulary](/advanced/online-vocabulary/) for that lifecycle.
