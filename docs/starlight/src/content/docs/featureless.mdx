Traditional ML models, and all of our competitors in the space of relational learning, rely on expert feature engineering and even learned pre-processors to contextualize how one data sample exists in relation to a studied population. Such approaches, while effective, can exacerbate the lifecycle of a predictive modeling project by several months, even years–and add significant complexity and overhead costs to production implementations of said ML models.

<FeatureEngineeringFlow />

In contrast to this, we built relflow to model data exactly as it exists. We approached this in two key ways:

1. relflow models begin their data contract with the raw data, and rely on online vocabularies and normalizers to contextualize how each observation of data exists in relation to a studied population.
2. We build dynamic model architecture in order to naturally mirror the structure which exists among relational data.

## Fully integrated feature pipelines

By internalizing feature processing pipelines as integrated model components, relflow natively supports the full machine learning lifecycle in enterprise applications. This provides:

- A cleaner boundary between data ingestion pipelines and the predictive model itself.
- Consistent model-owned feature processing during training and inference, using the same learned vocabularies and normalizers.
- Access to training category counts and numeric statistics for comparison with inference data, helping identify distribution changes.

## Dynamic model architecture

Dynamic model architecture allows us to build models well suited for arbitrarily nested or typed data. By integrating parent-child relationships directly into model design, we allow for the logical relationships between data points to be best presented to the model.
