relflow models are powerful because they allow related data to be studied by a model dynamically constructed to mirror a dataset’s natural relations. This is largely possible because of our unique application of context windows through the `branch` construct.

The attention described here operates within one top-level model observation. In a branch, fields within each record can attend to one another, and related records can attend across the collection. This implementation of cross-attention allows for interactions between:

- The co-incident datapoints within an observation
- Datapoints across different observations when packed into a branch

Set `cross=True` on a branch to mix its fields multiplicatively within each record. For example, in `rf.Branch(cross=True, quantity=rf.Number, unit_price=rf.Number)`, quantity can modulate the representation of unit price. The option applies only to that branch. Use `cross=True` on `rf.Model` to apply it to the root record.

As with all user-facing constructs in relflow, branches are defined with great user extensibility in both the length of a branch (the context-window), as well as what elements of ingested data fills the content of a branch. These aspects are discussed in greater technical depth in our [API map](/api-map/).

## Information reductions

In order to condense information as it flows vertically up the tree, from a leaf to the root, reductions are applied to the information contained within a branch.

Reductions occur after attention is applied within and across observations within a branch, and these reductions may take many forms. Further, these reductions allow for each branch of the model tree to potentially reduce the context size while traversing up the model tree. This embedding functions as the learned representation of all data contained under that branch.

Relflow currently offers reductions as a cross-attention, algebraic mean, or an identity forward-pass. For the attention-based reduction of information, users may explicitly declare the number of outputs of this reduction. The Mean branch reduction averages the encoded values while also retaining a learned count signal.

## Position records by their index

Attention within a branch normally measures how far apart two records are by their order in the collection: the third reading is two steps from the first, whether they were taken an hour or a month apart. Add an `rf.Index` to measure that distance with a value each record carries instead, such as a timestamp or a sequence number.

```python
class Reading(rf.Branch):
    """One sensor reading."""

    recorded_at = rf.Index(granularity="hours")
    temperature = rf.Number
    vibration = rf.Number


class Equipment(rf.Model):
    """One machine at its observation cutoff."""

    sensor_readings = Reading(length=168, overflow="tail")
    failure = rf.Boolean(predict=True)
```

An index is declared like a field but is a different kind of node, a twig: it shapes its branch rather than contributing a value to it.

- It reads one integer, date, or timestamp per record, from its own name or from `query`. Integers count their own units; dates and timestamps count `granularity` units, which default to days.
- The branch's attention and its attention reduction rotate each record by its index rather than its position in the collection. Only differences matter, so shifting every index by the same amount changes nothing, and records need not be sorted.
- The index is never embedded or predicted. To also learn from the same timestamp, add a field that reads it, such as `recorded_on = rf.Period("day_of_week", query="recorded_at")`.
- A branch holds at most one index, and every retained record needs a value. The model root holds one record per observation, so it cannot hold an index.
- The branch's `length` and `overflow` still count and crop records in their supplied order. Decoders and the parent branch still locate each record by its slot in the collection.

[Late-payment evidence](/evidence/P126/) compares an index with ordinal positions, a prepared elapsed-hours field, and donor timelines when the answer depends only on the hours between two records.
