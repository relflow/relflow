relflow models are powerful because they allow related data to be studied by a model dynamically constructed to mirror a dataset’s natural relations. This is largely possible because of our unique application of context windows through the `branch` construct.

For branches with multiple data entries (either as child leafs or as child branches), the forward pass of a context branch allows for each data entry to attend to each other entry within the same observation. Following this, each value from each observation within the length of a branch is allowed to attend to every other value from every other observation. This implementation of cross-attention allows for interactions between:

- The co-incident datapoints within an observation
- Datapoints across different observations when packed into a branch

As with all user-facing constructs in relflow, branches are defined with great user extensibility in both the length of a branch (the context-window), as well as what elements of ingested data fills the content of a branch. These aspects are discussed in greater technical depth in our [API map](/api-map/).

## Information Reductions

In order to condense information as it flows vertically up the tree, from the leaf to the node / root, reductions* are applied to the information contained within a branch. Reductions occur after the aforementioned process of attention within and across observations within a branch. These reductions may take many forms, as a cross-attention, algebraic mean, or an identity forward-pass in which nested information is presented, as is, to the next layer of the tree. Further, these reductions allow for each branch of the model tree to potentially reduce the context size while traversing up the model tree. This embedding functions as the learned representation of all data contained under that branch.
