All input data for relflow models is represented as the leaf of a model tree. As mentioned under [Modular Modeling](/modular/), relflow defines a plug-in registry for each data leaf; this registry enforces fulfillment of a contract in which:

- Raw data, in its nominal state, is passed to the leaf
- A vector of standard dimensionality (as determined by the model’s initialization) is emitted by the leaf and passed along the leaf’s heritage path.

## State vs Content

Every leaf promises to emit one vector per observation, an embedding which is learned to best represent the ingressed data. The standard relflow data leafs draw a distinction between two aspects of the observed data: state, and content.

The state of a data observation must be one of five distinct values, given in the below table:

| State | Meaning |
| --- | --- |
| <StateToken state="valued" /> | The data observed does exist, and is available for modeling purposes |
| <StateToken state="null" /> | The data observed does not exist (is an instance of `None`) due to missingness |
| <StateToken state="padded" /> | The data observed does not exist. |
| <StateToken state="masked" /> | The data observed does exist, but is intentionally hidden for model training / reconstruction |
| <StateToken state="other" /> | The data observed is not `None`, but it also is not of a usable value for modeling (this may be a `np.NaN` value for numerical representation, or a Vector with infinite values) |

This state value is incorporated into the same embedding which a relflow leaf emits as the data observation’s representation. The decoder of each leaf, unless otherwise stated, will decode the learned embedding into

1. A discrete `state` value, penalized by cross-entropy
2. A representation of the original content, penalized with unique loss functions for each leaf.

## Leaf Addresses

The heritage path of a data leaf describes where each leaf exists in relation to all, if any, parent branches. This heritage path is represented in a 1:1 manner with standard file-path addresses, where the root directory of a file-path represents a model object.

Critically, the default heritage path for a leaf is the assumed query path under which the leaf’s data exists, relative to the tensordict in which data is passed from a data loader (and optional pre-processor) into the model.

## Continuous data

- [Number](/data-types/number/) represents scalar measurements and numeric magnitudes.
- [Quantile](/data-types/quantile/) represents numeric values by their position in the training distribution.
- [Vector](/data-types/vector/) represents fixed-width numeric coordinates.
- [Ordinal](/data-types/ordinal/) represents ordered labels or integer ranks through numeric rank.

Choose Number when distances in the original units or predictions beyond the
observed range matter. Choose Quantile when relative position in the distribution
is the useful representation. Its learned range bounds its output and can merge
inputs beyond the same training tail. The retained checks cover
[range behavior](/evidence/#P068) and [objective differences](/evidence/#P077).

## Discrete data

- [Category](/data-types/category/) learns a vocabulary of labels.
- [Boolean](/data-types/boolean/) represents true-or-false values and predicts their probability.
- [Enum](/data-types/enum/) uses an explicitly declared vocabulary.
- [Hash](/data-types/hash/) preserves identifier relationships without a learned identity vocabulary.
- [Set](/data-types/set/) represents unordered label membership.
- [Group](/data-types/group/) learns shared representations for identities.

## Calendar data

- [Period](/data-types/period/) represents recurring calendar parts.
- [Duration](/data-types/duration/) derives elapsed time from timestamp endpoints.

## Multimodal data

- [Text](/data-types/text/) uses a frozen text encoder and learns how its representations contribute to the task.
