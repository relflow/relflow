Once you have defined a model, its runtime follows four methods: `fit`,
`validate`, `test`, and `predict`. Start with a preset so you can focus on your
data and prediction targets rather than configuring the training loop.

## Start with a preset

The bundled presets are `small` and `medium`. Select a preset when constructing
the model to choose its architecture defaults, and select it again on `fit` to
choose its training defaults. These are independent choices.

The examples below use `small` for both. Its fit recipe supplies the batch size,
optimizer settings, training budget, and parameter averaging. You do not need to
set those options individually to get started.

## Fit, validate, test, predict

| Method | Purpose | Returns |
| --- | --- | --- |
| `model.fit(data, preset="small")` | Train on historical examples with preset defaults. | The fitted model. |
| `model.validate(data)` | Evaluate the validation split while choosing a model. | A list of metric dictionaries. |
| `model.test(data)` | Evaluate the held-out test split after making model choices. | A list of metric dictionaries. |
| `model.predict(data, devices=1)` | Predict the answers for new request records. | An eager Polars DataFrame. |

Use a data module to stream prepared files from disk or cloud storage. Training,
validation, and test records include the historical target answers; prediction
requests supply the known inputs. The same schema applies throughout.

## Keep the fitted model

Use `model.save(...)` and `rf.Model.load(...)` to keep the schema, learned
parameters, and field state for later predictions. See
[checkpoints and model state](/advanced/checkpoints-and-state/) for persistence
and continuing a training run.

For custom sources or preprocessing, continue with
[data modules](/advanced/data-modules/). Training policy overrides and learned
state are covered in [Advanced Usage](/advanced/training/).
